# Milestone 3: AI Provider and Agent Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The admin connects an OpenAI-compatible AI provider, then asks the agent questions about this host in a chat. The agent answers by reading Vegapunk's stored data and live container logs, and it can change nothing.

**Architecture:** Provider settings (base URL, model, instructions, an encrypted API key) live in SQLite. A logpose `Agent` is built for each chat turn from those settings, with six read-only tools and one gate every tool call passes through. The reply streams to the browser as JSON lines. Conversations are logpose sessions in their own database file, with a list kept in Vegapunk's database for the History screen.

**Tech Stack:** Python 3.12, FastAPI, [logpose](https://github.com/xdadwal/logpose) v0.2.0, `cryptography` (Fernet); TypeScript, React 19, `fetch` streaming.

**Spec:** [`AGENTS.md`](../../AGENTS.md) ("First-version scope": observer mode, AI operator, logpose), [`roadmap.md`](roadmap.md) (milestone 3), [`known-issues.md`](../known-issues.md). Screens: the "Vegapunk MVP" canvas (`Setup`, `Settings`, `Assistant`, `History`, `States`) and the design system's `ChatThread`, `ChatMessage`, `Textarea` READMEs and its "Agent voice" section. Builds on [M2](2026-11-26-m2-capture.md), including its "Implementation notes".

## Decisions made in this plan

| # | Decision | Why |
|---|---|---|
| D1 | logpose v0.2.0, installed from its git tag; only its `openai-compat` provider | It speaks any OpenAI-compatible server (OpenAI, Ollama, vLLM, OpenRouter); not on PyPI yet |
| D2 | The API key is encrypted at rest with Fernet; the key file `secret.key` sits in the data directory with mode 0600 | Keeps the key out of a copied database or backup. It does **not** protect against someone who can read the whole data folder, and the README must say so |
| D3 | Conversations are logpose sessions in `conversations.db`; Vegapunk keeps its own `conversations` table (id, title, times) in `vegapunk.db` | logpose has no way to list sessions, and the History screen needs a list |
| D4 | The reply streams as newline-delimited JSON over a `POST` | `EventSource` cannot `POST`; reading a `fetch` body line by line is simple and testable |
| D5 | One chat answer at a time, server-wide; a second request gets 409. Each answer is limited to 8 model turns, 12 tool calls, 4,096 output tokens and 180 seconds. A message is at most 4,000 characters | One admin; stops a runaway loop from spending the admin's money |
| D6 | Six read-only tools: host overview, list containers, container details, container metrics, host metrics, container logs | Everything the screens show, plus logs, which are read live and never stored |
| D7 | Anything from a container that goes to the provider is redacted first (keys, tokens, passwords, URL credentials, JWTs, private keys), best effort and documented as such. Environment variables, mounts and labels are never read | The design promises "secrets redacted"; no tool is given access to the most sensitive Docker fields |
| D8 | Setup step 2 is a page shown once after the account is created, with "Skip, use Vegapunk without AI"; afterwards the same form lives in Settings | Matches the design; skipping must work |
| D9 | Times stay UTC; there is no time zone setting yet, and no per-message times in chat | logpose messages carry no timestamps; known limit, not worked around |
| D10 | "Agent" in the UI, "AI provider" only in settings (design voice rules) | Fixed terms from the design system |
| D11 | logpose's built-in context handling stays on. It adds one tool of its own, `recall_tool_output` (pages back through an earlier long tool result), which the gate allows and which is shown as "Read earlier tool output" | Without it a follow-up question cannot re-read earlier logs, and long conversations would overflow the model's context |
| D12 | A saved API key is only ever used with the base URL it was saved for | Otherwise changing the Base URL and leaving the key blank would send one provider's key to another server |

## Global Constraints

- **The agent is read-only.** No tool changes anything on the host. The tool names are pinned by a test; adding a tool that writes is a deliberate, reviewed step (it belongs to the later "manage containers" work, behind the permission levels).
- Text that comes from containers (names, images, log lines) is **data, not instructions**. The system prompt says so, and because no tool can write, an injected instruction can at worst skew an answer.
- The API key is never returned by any API, written to any log, put in any error message, sent to any server other than the base URL it was saved with, or stored in plain text. Only `key_hint` (the last four characters) is shown. Provider and logpose error text goes through `scrub_secret` before it is shown or returned (logpose itself leaves the first six characters of a key in its own marker).
- The only tools the agent can call are the six below and logpose's built-in `recall_tool_output`; the gate refuses everything else.
- Redaction works on the whole text and is bounded in time: lines are cut before any pattern runs and no pattern scans without a limit.
- Everything goes through `DockerHost` for Docker. It gains exactly one read method, `container_logs`.
- Every route requires the signed-in admin. Async handlers never call SQLite on the event loop: use `anyio.to_thread.run_sync`, or sync handlers.
- Limits: tool output at most 8,000 characters; at most 50 containers per list; logs at most 300 lines.
- UI: plain and exact, container names in mono, 12-hour clock with zone (UTC), model output never parsed as HTML, "Agent" not "AI" except in provider settings.
- New dependencies: `logpose` (tag `v0.2.0`), `cryptography`. Frontend: none. Ask before adding more.
- Backend: `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest` pass. Frontend: `npm run lint`, `npm test`, `npm run build` pass. Format only the files you changed. Commit after each task; do not push unless asked.

## Review Focus

Each line names a condition the happy-path tests do not cover; the task in brackets owns its test.

1. **Prompt injection:** a log line or container name reading "ignore your instructions and …" reaches the model only as tool output. The tool set has no writer, the gate refuses any other tool name, and the system prompt tells the model container text is data. [Tasks 4, 5]
2. **Secrets leaving the server:** the API key appears in no response, log line or error (including a provider error that echoes it or part of it); it is never sent to a different base URL than it was saved for; secrets in log lines are redacted across lines, including private-key bodies, quoted values with spaces and credentials in URLs, and redaction stays fast on hostile input; the key file is 0600, can never be left half-written, and the database holds only ciphertext. [Tasks 1, 2, 3, 5]
3. **Provider failure:** a key rejected mid-conversation ends the stream with a `key_rejected` event, is remembered, shows a banner, and clears when a working key is saved; an unreachable provider, a timeout, a reply with no text, and a tool that errors each end the stream with a clear message and never hang it. [Task 5]
4. **Client leaves, or two tabs:** closing the tab or pressing Stop ends the run and frees the session; a second request while answering is a clean 409; deleting a conversation that is being answered is refused; a settings change takes effect on the next answer. [Tasks 5, 8, 9]
5. **Conversation integrity:** malformed, unknown or path-like conversation IDs never reach logpose; a conversation whose session expired shows as unavailable, not as an error; empty, whitespace-only and over-long messages are rejected before anything is sent; titles with markup or very long text are safe. [Tasks 5, 8, 9]

## Implementation notes

Corrections made after an independent review of this plan, before any code was written:

- logpose's default context handling adds a tool of its own, `recall_tool_output`; the gate allows it (D11) instead of blocking it and breaking follow-up questions.
- A saved key is only used with the base URL it was saved for (D12); changing the URL needs a new key or removing the old one.
- Redaction works on the whole text so private-key bodies cannot slip through line by line, and it is bounded in time (a naive pattern took 12 to 15 seconds on one long line).
- JSON tool results drop trailing rows to fit instead of cutting off their start; only logs keep their tail.
- History and delete use a store-only agent so they work when AI is off; the test seams (`docker`, `make_agent`) and the "pull the first event before streaming" contract are spelled out.
- Error text is scrubbed of the key and of the first six characters logpose leaves in its own marker.

**Interfaces:**
- Produces:
  - `DockerHost.container_logs(container_id: str, tail: int) -> list[str] | None`: the last `tail` lines of stdout and stderr with timestamps, decoded as UTF-8 with replacement, one string per line, no trailing newline; `None` if the container no longer exists; `DockerError` on any other failure. Uses the SDK's `logs(tail=tail, timestamps=True, stdout=True, stderr=True)`. The "public surface" test now lists six methods.
  - `redact.redact(text: str) -> str`: replaces each secret with `[redacted]`. It works on the **whole text** (so a multi-line private key is caught) and is bounded in time: before any pattern runs, every line is cut to its first 2,000 characters, and every pattern limits what it can scan (a keyword may have at most 64 name characters either side; no unbounded `[\w.-]*`). Rules, in order:
    1. Private key blocks, `-----BEGIN … PRIVATE KEY-----` through `-----END … PRIVATE KEY-----`, across lines (an unterminated block redacts to the end of the text).
    2. `Authorization: Bearer|Basic|Token <value>` and any `Bearer <value>` of 8 or more characters: the value.
    3. `scheme://[user]:password@host`: the user (which may be empty, as in `redis://:pw@host`) and the password (`scheme://[redacted]@host`).
    4. JSON Web Tokens (`eyJ…​.eyJ…​.…`).
    5. Well-known prefixes: `sk-` followed by 16 or more characters of `[A-Za-z0-9_-]`, `ghp_`/`gho_`/`ghs_`/`github_pat_` tokens, `xox[baprs]-` tokens, and `AKIA` followed by 16 uppercase letters or digits.
    6. Values of keys whose names contain `password`, `passwd`, `pwd`, `secret`, `token`, `api_key`, `apikey`, `api-key`, `access_key`, `private_key` or `credential` (case-insensitive), written as `name=value`, `name: value` or `"name": "value"`. A value that starts with a quote runs to the matching closing quote (`password="two words"`, single quotes too); otherwise it runs to whitespace, a quote, a comma, a semicolon or `&`.
  - `redact.limit_text(text: str, max_chars: int) -> str`: unchanged if it fits; otherwise the **last** characters preceded by a first line `[earlier output omitted: N characters]`, with the whole result at most `max_chars` long (the note counts).
  - `redact.scrub_secret(text: str, secret: str | None) -> str`: removes the secret wherever it appears and, when it is at least 12 characters, its first six characters as well (logpose's own scrubbing leaves those in its `<redacted … len=N>` marker); then applies `redact`, and cuts the result to 300 characters. With no secret it only applies `redact` and the cut.

**Interfaces:**
- Produces (`crypto.py`):
  - `CryptoError(Exception)`, message safe to show.
  - `load_or_create_key(data_dir: Path) -> bytes`: reads `data_dir/secret.key`; if absent, writes a new Fernet key to a temporary file in the same directory (mode `0o600`) and hard-links it to `secret.key`, then removes the temporary file, so `secret.key` never exists half-written and a crash cannot leave an empty key file that blocks startup. If another process created it first, the existing file is used. An existing file with group or other permissions is tightened to `0o600`. A file that is not a valid Fernet key raises `CryptoError` naming the path; it is never regenerated (that would silently orphan the saved API key).
  - `encrypt(key: bytes, text: str) -> str`, `decrypt(key: bytes, token: str) -> str`; a token that cannot be decrypted raises `CryptoError("The saved API key can't be read. Enter it again.")`.
  - `key_hint(api_key: str) -> str`: `"…" + last four characters` when the key is at least 12 characters, else `"…"`.
- Migration `0003_agent.sql`:
  - `ai_settings(id INTEGER PRIMARY KEY CHECK (id = 1), base_url TEXT NOT NULL, model TEXT NOT NULL, instructions TEXT NOT NULL, api_key_encrypted TEXT, key_hint TEXT, key_rejected_at TEXT, updated_at TEXT NOT NULL)`
  - `conversations(id TEXT PRIMARY KEY, title TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL)` with an index on `updated_at`.
- Produces (`ai/store.py`):
  - `KEEP` sentinel. `AiConfig(base_url: str, model: str, instructions: str, api_key: str | None)` (frozen).
  - `LoadedAi(config: AiConfig, key_saved: bool, key_hint: str | None, key_rejected_at: datetime | None, key_unreadable: bool)`; when the key cannot be decrypted, `config.api_key` is `None` and `key_unreadable` is true.
  - `load_ai(conn, key: bytes) -> LoadedAi | None`: `None` when nothing is saved.
  - `save_ai(conn, key: bytes, *, base_url: str, model: str, instructions: str, api_key: str | None | KEEP, now: datetime) -> None`: one `db.transaction`. `KEEP` leaves the stored key alone, `None` removes it, a string replaces it (stored encrypted, with its hint). Saving always clears `key_rejected_at`. Validation (raises `ValueError` with a message safe to show): `base_url` starts with `http://` or `https://`, is at most 2,048 characters, has no whitespace, and is stored without a trailing `/`; `model` is 1 to 200 characters after trimming; `instructions` at most 4,000; `api_key` at most 500 characters and no surrounding whitespace is kept (it is stripped).
  - `clear_ai(conn) -> None`; `mark_key_rejected(conn, now: datetime) -> None` (no-op when nothing is saved).
  - `add_conversation(conn, id: str, title: str, now: datetime) -> None`, `touch_conversation(conn, id: str, now: datetime) -> None`, `list_conversations(conn, limit: int = 200) -> list[dict]` (`id`, `title`, `updated_at` ISO `Z`, newest first), `get_conversation(conn, id: str) -> dict | None`, `delete_conversation(conn, id: str) -> None`, `make_title(message: str) -> str` (whitespace collapsed, at most 60 characters, an ellipsis when cut, `"New conversation"` if empty).

- Produces (all require sign-in):
  - `GET /api/settings/ai` → `{"configured": bool, "base_url": str, "model": str, "instructions": str, "key_saved": bool, "key_hint": str|null, "key_rejected_at": iso|null, "key_unreadable": bool}`. Nothing saved: `configured: false`, `base_url: "https://api.openai.com/v1"`, empty `model` and `instructions`, `key_saved: false`.
  - `PUT /api/settings/ai` with `{"base_url": str, "model": str, "instructions": str, "api_key": str|null, "remove_key": bool}` (`api_key` omitted or null keeps the stored key; `remove_key: true` removes it; a string replaces it) → same shape as GET. Validation failures are 422 with a readable `detail` string. A saved key is kept only for the base URL it was saved with: when a key is saved, the request's normalised `base_url` differs from the saved one, and the request neither sends a new `api_key` nor sets `remove_key`, the answer is 422 with `You changed the Base URL, so enter the API key again, or remove the saved key.`
  - `DELETE /api/settings/ai` → 204; idempotent; turns the agent off.
  - `POST /api/settings/ai/test` with `{"base_url": str, "api_key": str|null}` (a null key uses the saved key **only when the normalised `base_url` equals the saved base URL**, so the admin can test without retyping; for any other URL no key is sent) → always 200 with `{"ok": true, "models": [str]}` (sorted, at most 200) or `{"ok": false, "code": "key_rejected"|"unreachable"|"error", "message": str}`. `AuthError` is `key_rejected` ("The server rejected the API key."); a `ProviderError` with no HTTP status (the server could not be reached) or a timeout after 15 s is `unreachable` ("Couldn't reach {base_url}."); any other failure, including an HTTP error such as 404, is `error` with the message passed through `scrub_secret(message, key)`; for a 404 the message is prefixed `Check the Base URL; it usually ends in /v1.` The provider is built with `app.state.make_provider(base_url=..., api_key=key or "")` and closed afterwards. A successful test of the saved settings clears `key_rejected_at`.
