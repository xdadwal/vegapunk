# Milestone 2: Capture and Read-only Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server periodically captures the host's CPU, memory and storage and every Docker container's state and usage, stores them with short-term detail and 30 days of history, and shows them on Overview, Containers and Container detail.

**Architecture:** Collectors read the host only through a read-only `host/` module and turn what they read into normalized records. One `ingest` function stores records; a scheduler thread inside the server runs the collectors every 15 seconds and rolls samples up into 5-minute averages. The API reads only from the database. The UI polls the API every 5 seconds.

**Tech Stack:** Python 3.12, FastAPI, stdlib `sqlite3`, `docker` (Docker SDK), `psutil`; TypeScript, React 19, hand-written SVG charts.

**Spec:** [`AGENTS.md`](../../AGENTS.md) ("First-version scope", "Architecture"), [`roadmap.md`](roadmap.md) (milestone 2). Screen designs: the "Vegapunk MVP" canvas (`Main`, `Containers`, `Container`, `States`) and the design system's `Stat`, `Sparkline`, `StatusBadge`, `ServiceRow`, `TimeSeriesChart` READMEs. Builds on [`2026-11-26-m1-foundation.md`](2026-11-26-m1-foundation.md), including its "Implementation notes".

## Decisions made in this plan

These were chosen after probing Docker 29 and psutil from a non-root container. Change one and the tasks that name it change with it.

| # | Decision | Why |
|---|---|---|
| D1 | Container CPU is a share of the whole host (0 to 100), the same scale as host CPU | One scale on every screen; Docker's own tool shows 100 per core |
| D2 | "Storage" is the filesystem Docker keeps its data on: the container's own `/`, with `VEGAPUNK_DISK_PATH` to point at another mounted folder | Needs no mount, and it is the disk containers fill. One filesystem now; a per-filesystem list comes later |
| D3 | Capture every 15 s; keep raw samples 24 h and 5-minute averages 30 days | Matches the roadmap; about 5,760 raw rows per series per day |
| D4 | The container runs as a non-root user and reaches the Docker socket through `group_add: ${DOCKER_GID}` | Keeps the web process non-root. On Linux the socket's group is the `docker` group, and its id differs per host |
| D5 | Containers are keyed by Docker id in the database and by name in URLs; a recreated container (same name, new id) starts a fresh history | Names are what people use; compose recreates containers on deploy |
| D6 | The UI polls every 5 s and pauses while the tab is hidden | No push channel needed yet |
| D7 | New dependencies: `docker`, `psutil` (backend). Frontend: none; charts are SVG | Ask before adding more |
| D8 | CPU, memory and uptime come from the container's own `/proc`; the host's `/proc` is not mounted | `/proc/stat` and `/proc/meminfo` are already host-wide for an ordinary container (checked: identical `MemTotal`). Mounting the host's `/proc` would let the web process see every host process (181 instead of 2). Hosts that use `lxcfs` would report per-container values; not supported |
| D9 | Container lists are filtered in the browser, and the API has no filters | A homelab has tens of containers; this removes query escaping and a second place for the status rules |

## Global Constraints

- **Read-only.** Nothing in this milestone changes the host. `host/docker.py` exposes only reads (`ping`, `info`, `version`, `list_containers`, `container_stats`); no other method may call Docker. Every Docker call has a 5-second timeout.
- Capture runs in a single scheduler thread; the server runs one uvicorn worker.
- A source that fails (Docker unreachable, one container vanishing mid-read) must never stop the other sources or the next cycle.
- Never mark containers removed because a listing failed. "Docker could not be read" and "no containers exist" are different facts.
- All stored and returned timestamps are UTC. The API returns ISO-8601 with `Z`; the database stores Unix seconds for samples and ISO text elsewhere.
- Memory shown for a container excludes reclaimable page cache (Docker's own convention: usage minus `inactive_file`).
- Every API route requires the signed-in admin (`require_admin`). New writes go through `db.transaction`.
- UI copy: plain and exact, container names in mono, "Agent" not "AI", 12-hour clock with zone (UTC), colour only for problems (design system "Content fundamentals").
- Backend: `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest` pass. Frontend: `npm run lint`, `npm test`, `npm run build` pass. Commit after each task; do not push unless asked.

## Review Focus

Each line names a condition the happy-path tests do not cover; the task in brackets owns its test.

1. **Docker unreachable at startup or mid-run:** the server still starts, containers already stored stay listed and are not marked removed, the UI shows "Can't reach Docker" with the reason, and the alert clears when Docker returns. [Tasks 2, 4, 8]
2. **A container deleted while Docker is being listed, or between listing and stats:** the listing still returns the others, that container's sample is skipped, and the cycle succeeds. A redeploy mid-cycle must not show "Can't reach Docker". [Tasks 1, 3]
3. **CPU counters that reset when a container restarts, and the first sample after startup:** show no value, never a negative or huge one. [Task 3]
4. **Two containers with the same name (an old exited one and its recreated replacement):** the list and detail resolve to the live one, and a name never appears twice among live containers. [Tasks 2, 6]
5. **Host off or the server stopped for days:** the next cycle stores normally, pruning keeps the newest data, and ranges with no samples return an empty list, not an error. [Tasks 5, 6]
6. **Unlimited container memory:** Docker reports the host's total as the limit; show "no limit", not a percentage of the host. A container that is not running has no sample at all; show "—". [Tasks 3, 9]

**Interfaces:**
- Produces:
  - `Settings` gains fields with defaults, so existing constructions keep working: `capture: bool = False` (start the scheduler), `capture_interval: int = 15` (seconds, at least 1), `docker_url: str = "unix:///var/run/docker.sock"`, `disk_path: Path = Path("/")`. `load_settings` returns `capture=True` (the real server always captures; tests build `Settings` directly and leave it off) and reads `VEGAPUNK_CAPTURE_INTERVAL` (default `15`), `VEGAPUNK_DOCKER_URL`, `VEGAPUNK_DISK_PATH`. A non-integer, zero or negative interval raises `ValueError` naming the variable.
  - `docker.DockerError(Exception)`: its message is safe to show people.
  - `docker.DockerHost(url: str, client: DockerClientLike | None = None)` with only these public methods: `ping() -> None`, `info() -> dict`, `version() -> str`, `list_containers() -> list[dict]`, `container_stats(container_id: str) -> dict | None`.
    - It builds `docker.DockerClient(base_url=url, timeout=5)` lazily on first use. The SDK connects inside that constructor, so a failed build raises there; the failed client is not cached and the next call tries again.
    - `list_containers` calls `containers.list(all=True, ignore_removed=True)` and returns each container's raw `attrs`. Collectors read only: `Id`, `Name` (Docker prefixes it with `/`), `Config.Image`, `State.Status`, `State.Health.Status` (absent when there is no health check), `State.StartedAt`, `RestartCount`.
    - `container_stats` calls the SDK with `stream=False, one_shot=True` and returns `None` if the container no longer exists.
    - Every method converts failures into `DockerError`, walking the exception's `__cause__` and `__context__` chain: a `PermissionError` anywhere in it gives "Vegapunk can't read the Docker socket at {url}. Set DOCKER_GID to the group that owns it."; a `FileNotFoundError` or connection error gives "Can't reach Docker at {url}."; anything else gives the exception's text.
  - `system.SystemHost(disk_path: Path)` with `cpu_percent() -> float | None` (host-wide, 0 to 100; the first call only primes psutil and returns `None`), `memory() -> tuple[int, int]` (used, total; used is total minus available), `disk() -> tuple[int, int]` (used, total of `disk_path`), `boot_time() -> datetime` (aware UTC). Constructing it never touches `/proc`, so it cannot fail at startup.

### Task 3: Collectors

**Files:**
- Create: `backend/vegapunk/capture/collectors.py`
- Test: `backend/tests/test_collectors.py`

**Interfaces:**
- Consumes: `DockerHost`, `SystemHost`, `DockerError`, the records.
- Produces:
  - `collectors.SOURCES = ("host", "docker")`: the collector names, used by the scheduler and the API.
  - `collectors.Collector` (Protocol): `name: str`; `collect(now: datetime) -> list[Record]`; raises (`DockerError` or any `Exception`) when the source cannot be read.
  - `collectors.HostCollector(system: SystemHost)`, `name = "host"`: returns `[HostSample]`.
  - `collectors.DockerCollector(docker: DockerHost)`, `name = "docker"`: returns `[HostFacts, ContainerList, *ContainerSample]`, calling `info()`, `version()`, `list_containers()` and then `container_stats` for each container whose state is `running`. Containers in any other state (including `restarting`) get no sample. It keeps each running container's previous raw CPU counters in memory and forgets those of containers that are gone.
  - `collectors.cpu_percent(previous: tuple[int, int] | None, current: tuple[int, int] | None) -> float | None`: each tuple is `(container_cpu_ns, system_cpu_ns)`; the result is `(Δcontainer / Δsystem) * 100` clamped to 0 to 100, or `None` if either is missing, Δsystem is not positive, or a counter went backwards.
  - `collectors.memory_used(stats: dict) -> int | None`: `usage` minus the first present of `total_inactive_file`, `inactive_file`, `cache` (the order Docker's own CLI uses across cgroup v1 and v2) read from `stats["stats"]`; never below 0; `None` when `usage` is absent.
  - `collectors.memory_limit(limit: int | None, host_mem_total: int) -> int | None`: `None` when the limit is absent or at least the host's total memory (`info()["MemTotal"]`).

### Task 4: Scheduler and capture status

**Files:**
- Create: `backend/vegapunk/capture/scheduler.py`
- Modify: `backend/vegapunk/app.py`, `backend/tests/conftest.py`
- Test: `backend/tests/test_scheduler.py`

**Interfaces:**
- Consumes: `Collector`, `SOURCES`, `ingest`, `db.connect`, `db.transaction`; `rollup`/`prune` are wired in during Task 5.
- Produces:
  - `scheduler.Scheduler(db_path: Path, collectors: Sequence[Collector], interval: int, clock: Callable[[], datetime] = utcnow)`.
  - `Scheduler.run_once() -> None`: one cycle. For each collector in order: call `collect(now)` and ingest the records. On success set its `capture_status` row (`last_attempt_at = last_success_at = now`, `last_error = NULL`). On any exception, from `collect` or from ingest, set `last_attempt_at = now` and `last_error` to the error text (for an ingest failure: `Couldn't store data: …`), leave `last_success_at` as it was, and carry on with the next collector. Never raises.
  - `Scheduler.start() -> None` and `Scheduler.stop() -> None`: a daemon thread that runs `run_once` immediately, then every `interval` seconds measured from the start of the previous cycle (a slow cycle shortens the wait and never overlaps the next). `stop` sets an event and joins within 5 seconds.
  - `app.create_app(settings: Settings, collectors: Sequence[Collector] | None = None) -> FastAPI`. The lifespan records `app.state.started_at` (aware UTC). When `settings.capture` is true it builds a `Scheduler` with `collectors`, or with the real ones (`HostCollector`, `DockerCollector`, built from `settings`) when `collectors` is `None`, starts it after migrations, and stops it on shutdown. When `settings.capture` is false, no thread starts.
  - `conftest.py` gains a `db_path(settings) -> Path` fixture that creates the data directory, migrates the database and returns its path.

  - `rollup.rollup(conn, now: datetime) -> None`: for the buckets containing the last 10 minutes up to `now` (including the current, partial one), write one `res = 300` row per series per bucket holding the average of the raw rows in it (`INSERT OR REPLACE`, so repeating it is harmless). A bucket with no raw rows writes nothing. Averages of integer columns are rounded to integers; nulls are ignored, and a column that is null in every raw row stays null.
  - `rollup.prune(conn, now: datetime) -> None`: delete raw rows older than `RAW_KEEP` and roll-up rows older than `ROLLUP_KEEP`; delete containers removed more than 30 days ago together with their metrics. Never deletes a row newer than the cutoff, whatever the gap since the previous sample.
  - The scheduler calls `rollup` once per cycle, after all collectors have run, if at least one of them ingested; and `prune` at most once per hour.

  - `GET /api/host` →
    ```json
    {"hostname": str|null, "os": str|null, "kernel": str|null, "docker_version": str|null,
     "cpu_count": int|null, "boot_time": iso|null,
     "latest": {"observed_at": iso, "cpu_pct": float|null, "mem_used": int, "mem_total": int,
                "disk_used": int, "disk_total": int} | null,
     "containers": {"total": int, "running": int, "needs_attention": int},
     "capture": {"interval_seconds": int, "sources": {"host": Source, "docker": Source}}}
    ```
    where `Source = {"ok": bool, "stale": bool, "last_success_at": iso|null, "error": str|null}`. `ok` is true when the last attempt succeeded; `error` is the last error text while `ok` is false; a source that has never run is `ok: false, error: null`. `stale` is true when more than 3 intervals have passed since `last_success_at`, or since `app.state.started_at` if there has never been a success. `latest` is the newest raw host row. `total` counts live containers; `running` counts status `online`; `needs_attention` counts `degraded` and `offline`.
  - `GET /api/host/metrics?range=1h|6h|24h|7d|30d` → `{"range", "resolution_seconds", "points": [{"ts": iso, "cpu_pct", "mem_pct", "disk_pct"}]}`, oldest first. `1h` reads raw rows (`resolution_seconds` is the configured interval); `6h` and `24h` read 5-minute roll-ups (300); `7d` and `30d` average those into hourly points (3600), so no range returns more than about 720 points. Percentages are `used / total * 100` rounded to one decimal, `null` when an input is null. No rows gives `points: []`. Any other `range` gives 422.
  - `GET /api/containers` → `{"total": int, "items": [Item]}`, with `Item = {"id", "name", "image", "state", "health": str|null, "status", "removed": false, "restart_count", "started_at": iso|null, "cpu_pct": float|null, "mem_used": int|null, "mem_limit": int|null}`. Live containers only. If two live rows share a name only the most recently seen is returned. Sorted offline, degraded, unknown, online, then by name. `cpu_pct`, `mem_used` and `mem_limit` come from the newest raw sample only if it is under 3 intervals old, else `null`. No filters: the browser filters (D9).
  - `GET /api/containers/{name}?range=…` → `Item` (with `removed` true when it is a removed container) plus `"metrics": {"range", "resolution_seconds", "points": [{"ts", "cpu_pct", "mem_used", "mem_limit"}]}`. Resolves to the live container with that name, else the most recently seen removed one. A removed container has `status: "offline"` and null `cpu_pct`, `mem_used`, `mem_limit`. `{name}` must match Docker's own rule `^[a-zA-Z0-9][a-zA-Z0-9_.-]*$`; anything else, or an unknown name, is 404 `{"detail": "No container named …"}`. (Encoded slashes never reach a route, so they cannot be supported.)
